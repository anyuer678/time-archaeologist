# 时光考古机 Time Archaeologist

本地优先的数字资产考古工具（Windows 桌面）。只读扫描项目目录的文件元数据、目录结构与内容签名，
构建项目活动时间线与成果证据链，帮你发现项目留下的真实成果、未完成任务和缺失证据。

**它不是**文件管理器、待办清单、知识库或 AI 聊天工具。

## 技术栈

- Python 3.12 + Tkinter（标准库，无第三方依赖）
- SQLite（WAL 模式，`synchronous=FULL`）
- 数据库位置：`%LOCALAPPDATA%\TimeArchaeologist\time_arch.db`（可用环境变量 `TIME_ARCH_DB` 或启动参数 `--db <路径>` 覆盖）

## 使用说明

**基本流程：**

1. **登记项目**：左侧「登记项目」选择要考古的目录（只读，不会动里面任何文件），登记后可立即扫描。
2. **扫描**：选中项目后点「重新扫描」。顶部扫描状态条实时显示已扫描文件数、已哈希体积、
   错误数和当前文件；随时可「取消扫描」（部分快照自动回滚，之后可安全重扫）。
3. **看结果**：主区五个页签——
   - **项目概览**：项目信息、最近活动、文件画像（各类别文件数 / 体积 / 最近文件时间）、快照历史。
   - **活动时间线**：全部事件，可按项目、事件类型、文件类别、关键词、日期范围过滤（即全局搜索），
     每页 200 条分页加载。
   - **最近发现**：全部项目最近 30 条事件。
   - **成果证据**：启发式识别的可执行文件 / 发布包 / 测试报告 / 实验产物 / 日志证据，
     附置信度与判断依据；可对每条做「人工确认」或「人工否决」。
   - **快照对比**：任选两次完成的扫描，列出新增 / 删除 / 修改文件清单。
4. **追溯证据**：任何事件或成果线索**双击**即可查看证据链——判断依据、涉及快照、
   关联文件记录（大小 / mtime / SHA-256 / 类别）；查不到文件记录时明确显示"证据不足"。
5. **导出报告**：右上角「导出报告」，选 Markdown（人读）或 JSON（机读）。

**如何看懂确定性标记：**

| 标记 | 含义 |
|---|---|
| 观察事实 (observed) | 两次扫描之间直接观察到的变化（新增 / 删除 / 内容签名变化） |
| 推测 (inferred) | 启发式推断，界面以 ※ 标注（如"日志生成"“产物出现”） |
| 启发式 (auto) | 成果线索的自动判断，附 high / medium / low 置信度 |
| 人工确认 (confirmed / rejected) | 你在成果证据页做出的裁决，导出报告中会体现 |

**重要提醒**：文件修改时间（mtime）只是文件系统时间戳，本工具绝不把它当作真实工作时间；
仅 mtime 变化而内容签名（SHA-256）不变时，不算"修改"。

## 架构

```
time_arch/
├── db.py        SQLite 持久层（projects / scan_runs / snapshots / file_records /
│                events / findings；每操作短事务；打开时自动把遗留 running 标记 interrupted）
├── scanner.py   只读扫描（自写 scandir 栈式遍历，跳过符号链接目录；SHA-256 分块
│                可取消；分批提交；取消/异常回滚快照；对比生成事件）
├── classify.py  文件类别启发式（源码/配置/测试/文档/日志/数据/构建产物）
├── analyze.py   成果考古启发式（可执行文件/发布包/测试报告/实验产物/日志证据）
├── reports.py   Markdown / JSON 报告导出
├── util.py      时间/路径/长路径前缀等工具
└── ui/          Tkinter 深色界面（theme.py 主题 + app.py 主窗口）
tests/           unittest 测试（classify / db / scanner / analyze_reports / recovery）
scripts/         ui_smoke.py 冒烟、acceptance_check.py 验收
```

## 安全承诺

- 只读扫描：仅 `stat / scandir / open(rb)`，验收脚本以全目录前后指纹比对验证。
- 不执行被扫描目录中的任何脚本或程序；不联网、不调用云端 AI、不需要管理员权限。
- 取消：worker 每读 1 MiB 检查一次取消标志，取消后回滚该次部分快照，可直接安全重扫。
- 崩溃恢复：进程被硬杀后，WAL 保证库文件不损坏（已用子进程 `os._exit` 实测）；
  遗留的 running 扫描在下次打开数据库时自动标记 interrupted，可立即重扫。

## 已知限制

- 取消采用「回滚 + 从头重扫」语义，未实现逐文件断点续扫（大目录重扫代价 = 重新哈希）。
- 扫描为单线程（遍历 + 哈希串行）；按实测首扫约 1000 文件/秒，十万文件级目录首扫需
  数分钟；重扫因增量缓存通常快一个数量级。
- 增量哈希以 size+mtime 判定"未变"：内容被篡改且时间戳被刻意还原的极端文件会被
  漏检（rsync/git 同款折衷）。
- 事件按 (run_id, event_type, rel_path) 去重；同一文件在一次扫描间隔内「改了又改回」只表现为无事件。
- 首次扫描会为全部现存文件生成基线事件（依据注明"登记时已存在，出现时间未知"）。
- 成果识别基于路径/扩展名启发式，不做内容级鉴定（不解析 zip/jar 内部）。
- 文件时间线只回溯到首次登记时刻，无法考古登记之前的历史。
- Windows 之外的平台界面字体/长路径行为未验证。
